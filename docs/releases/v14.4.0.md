# Zotero TaskFlow v14.4.0 发布说明

发布日期：2026-11-05
适用架构：现代 esbuild + TypeScript 模块化构建流水线架构（全面对齐 Zotero Flow 统一构建工程标准）

## 1. 核心改进与技术架构升级

- **彻底告别覆盖式结构：全面迁移至现代 TypeScript + ESM 源码架构**：
  - 将原本分散在历史覆盖目录的宿主核心代码全面重构至 `src/` 模块化目录体系；
  - 建立类型化领域模块：
    - `src/config.ts`：插件元数据、偏好设置默认值与运行时常量；
    - `src/taskRules.ts`：纯函数学术任务规则引擎与状态机（并发代数锁、定时器指纹、备份清洗）；
    - `src/literatureWorkflow.ts`：文献关联、精读流程与学术日历流转规则；
    - `src/itemPane.ts`：文献详情侧栏 Web Component 交互控制与原生 DOM 挂载；
    - `src/index.ts`：现代化宿主主类与多窗口生命周期调度引擎。
- **构建命令与工程流水线统一（对齐全系 esbuild/TS 标准）**：
  - 新增 `tsconfig.json` 与全局 Gecko/Zotero 运行时代数声明 `src/types/zotero.d.ts`，支持严格的静态类型检查；
  - 引入 `esbuild` 现代高速编译流水线 `scripts/build-source.mjs`，以 `src/index.ts` 为唯一宿主入口，自动打包并输出符合 Firefox 140+ / Gecko 153+ 标准运行时的单一自包含 IIFE 主包 `chrome/content/scripts/index.js`；
  - 全面统一 `package.json` 中的构建脚本体系：
    - `npm run tsc`：执行全量 TypeScript 静态类型检查（0 错误通过）；
    - `npm run build:source`：执行 esbuild 模块化编译打包；
    - `npm run build`：一键全自动完成 TypeScript 类型检查、esbuild 编译、XPI 归档生成与 SHA-512 校验和同步；
    - `npm test`：构建前置自动化校验并运行全部 158 项自动化测试；
  - 彻底解决了 TaskFlow 过去作为历史覆盖式项目“不能套用同一套构建命令”的异构问题，使其完全融入 Zotero Flow 全系统一工程基准。
- **现代化无重启生命周期与动态 Chrome 注册闭环**：
  - `bootstrap.js` 全面遵循无重启契约规范，通过 `aomStartup.registerChrome` 动态注册 `chrome://taskflow/` 命名空间，在插件卸载/禁用时通过 `chromeHandle.destruct()` 干净销毁，不再强依赖旧式静态 `chrome.manifest` 覆盖注入；
  - `bootstrap.js` 的 `startup()` 优雅收敛为仅加载打包生成的统一主脚本 `index.js`，告别历史多文件散装脚本注入。

## 2. 验证结果

- **TypeScript 类型检查**：`npm run tsc` 0 error 严格通过。
- **esbuild 模块编译**：`npm run build:source` 编译 `src/index.ts` 输出 188KB 纯净 IIFE bundle。
- **包构建与校验**：`npm run build` 产物 `zotero-taskflow-14.4.0.xpi` 自动生成，`update.json` 的 `sha512` 校验和 100% 吻合。
- **全套自动化测试**：`npm test` 包含 158 项单元/集成测试与打包测试全部绿灯通过（0 fail）。
